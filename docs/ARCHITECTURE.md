# 项目架构

## 概述

生存确认服务采用分层架构设计，确保代码的可维护性和可扩展性。

## 核心组件

### 1. Web服务层 (`src/web/`)
- **职责**: 提供HTTP服务和API接口
- **组件**: 
  - 路由管理
  - 中间件处理
  - 静态文件服务
  - 模板渲染

### 2. API处理层 (`src/api/`)
- **职责**: 处理HTTP请求和响应
- **组件**:
  - 请求处理器 (`src/api/handlers/`)
  - 中间件 (`src/api/middleware/`)
  - 响应格式化 (`src/api/response/`)
  - 错误处理和参数验证

### 3. 业务逻辑层 (`src/state/`)
- **职责**: 状态管理和业务逻辑
- **组件**:
  - 状态存储
  - 业务规则处理
  - 数据验证
  - 事务管理

### 4. 服务层
- **邮件服务** (`src/email/`): 处理邮件发送、重试机制、模板管理
- **配置服务** (`src/config/`): 配置文件管理和验证
- **任务调度器** (`src/scheduler/`): 定时任务和状态检查

## 数据流架构

```
用户请求 → Web路由 → API处理器 → 业务逻辑 → 内存状态
    ↓
定时任务 → 状态检查 → 邮件发送 → 配置文件读取
```

## 关键设计模式

### 1. 依赖注入
- 使用依赖注入管理服务之间的依赖关系
- 提高代码的可测试性和可维护性

### 2. 中间件模式
- Web请求处理使用中间件进行横切关注点处理
- CORS、日志、认证等通过中间件实现

### 3. 配置驱动
- 所有配置通过YAML文件管理
- 支持热重载和环境变量覆盖

### 4. 内存存储
- 签到时间存储在内存中
- 使用读写锁保证线程安全

## 核心模块说明

### 1. 配置管理模块
- **文件**: `src/config/config_manager.go`
- **功能**: 统一管理应用配置
- **特性**: 支持热重载、环境变量、配置验证

### 2. 状态管理模块
- **文件**: `src/state/state_manager.go`
- **功能**: 管理用户签到状态和系统状态
- **特性**: 内存存储、线程安全、状态变更记录

### 3. 邮件服务模块
- **文件**: `src/email/email_service.go`, `src/email/retry_manager.go`, `src/email/constants.go`
- **功能**: 处理邮件发送逻辑、重试机制、模板管理
- **特性**: SMTP支持、模板渲染、指数退避重试、Markdown转HTML

### 4. 任务调度模块
- **文件**: `src/scheduler/scheduler.go`
- **功能**: 定时检查用户状态、发送提醒邮件和遗书
- **特性**: 定时任务、提醒机制、优雅退出、生存检测停止

### 5. Web服务模块
- **文件**: `src/web/router.go`
- **功能**: 提供Web界面和API接口
- **特性**: RESTful API、中间件支持、静态文件服务

## 技术选型理由

### 1. Go语言
- **高性能**: 适合高并发场景
- **简洁**: 语法简单，学习成本低
- **跨平台**: 支持多平台编译
- **丰富生态**: 有成熟的第三方库

### 2. Gin框架
- **轻量级**: 性能优秀
- **中间件**: 灵活的中间件机制
- **路由**: 强大的路由功能
- **社区**: 活跃的社区支持

### 3. Viper配置管理
- **多格式**: 支持YAML、JSON、TOML等
- **环境变量**: 支持环境变量覆盖
- **热重载**: 支持配置热重载
- **验证**: 内置配置验证

### 4. 内存存储
- **简单**: 无需数据库依赖
- **快速**: 内存访问速度快
- **轻量**: 减少部署复杂度
- **适合**: 当前业务场景足够

## 扩展性考虑

### 1. 水平扩展
- 无状态设计，支持多实例部署
- 可以通过负载均衡器分发请求

### 2. 功能扩展
- 模块化设计，便于添加新功能
- 插件化架构，支持第三方集成

### 3. 存储扩展
- 当前使用内存存储，未来可扩展到数据库
- 配置管理支持多种存储后端

### 4. 监控扩展
- 预留健康检查接口
- 支持日志收集和监控

## 核心功能特性

### 1. 智能提醒系统
- 在发送遗书前发送提醒邮件
- 可配置提醒时间间隔
- 签到后自动重置提醒状态

### 2. 邮件重试机制
- 指数退避算法重试
- 支持从1秒到1周的重试间隔
- 自动重试失败的邮件发送

### 3. Markdown支持
- 遗书内容支持Markdown格式
- 自动转换为精美的HTML邮件
- 支持复杂的格式化内容

### 4. 生存检测停止
- 遗书发送后自动停止生存检测
- 避免重复发送遗书
- 提高系统的可靠性

### 5. 配置热重载
- 支持运行时重新加载配置
- 无需重启服务即可更新配置
- 提高系统的可维护性
